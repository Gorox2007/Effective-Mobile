# Практика 13. Распределённая система обмена сообщениями

Проект реализует адресный обмен сообщениями через WebSocket с многопроцессной обработкой и хранением сообщений для временно отключённых клиентов.

Реализовано:

- WebSocket-сервер на `ws`;
- несколько серверных воркеров через `cluster`;
- один отдельный БД-воркер;
- хранение сообщений для офлайн-клиентов в SQLite;
- выдача накопленных сообщений при повторном подключении;
- 10 клиентских воркеров `client-0` ... `client-9`;
- у клиентов есть счётчики отправленных и полученных сообщений по парам.

## Как запустить сервер

```bash
npm start
```

Сервер будет доступен по адресу:

```text
ws://127.0.0.1:8080
```

Если порт `8080` занят, можно запустить на другом порту:

```bash
PORT=8090 npm start
```

## Как запустить демонстрацию

Демонстрационный запуск:

```bash
npm run demo
```

По умолчанию создаются 10 клиентов. Каждый клиент отправляет 1000 сообщений случайным другим клиентам.
После завершения отправки программа печатает итоговую проверку матрицы и сама завершает работу.

Полный нагрузочный запуск:

```bash
npm run demo:full
```

В этом режиме создаются 10 клиентов, каждый отправляет 100000 сообщений.
Такой запуск сильно нагружает компьютер, поэтому его лучше запускать только при необходимости.

Быстрый тест, чтобы не ждать долго:

```bash
npm run demo:test
```

В быстром тесте запускаются 3 клиента, каждый отправляет 30 сообщений.

## Что делает каждый файл

- `src/main.js` - главный процесс. Он запускает остальные процессы, слушает WebSocket-порт и передаёт события подключений серверным воркерам через IPC.
- `src/server-worker.js` - серверный воркер. Он обрабатывает сообщения назначенных клиентов и хранит локальный список подключённых клиентов.
- `src/db-worker.js` - отдельный БД-воркер. Только он работает с SQLite.
- `src/client-worker.js` - клиентский воркер. Подключается к серверу, регистрируется и отправляет сообщения другим клиентам.
- `src/config.js` - настройки порта, количества клиентов, количества сообщений.
- `src/helpers.js` - маленькие общие функции.

## Как работает доставка

1. Клиент подключается и отправляет серверу своё имя.
2. Серверный воркер запоминает клиента у себя в локальном кэше.
3. Главный процесс запоминает, на каком воркере находится клиент.
4. Если сообщение отправлено онлайн-клиенту, оно сразу пересылается его воркеру.
5. Если получатель офлайн, сообщение сохраняется в SQLite через БД-воркер.
6. Когда получатель снова подключается, сервер спрашивает БД-воркер про его сообщения.
7. После успешной отправки накопленные сообщения удаляются из базы.

## Архитектура запуска

Порт `8080` слушает главный процесс.
Серверные воркеры получают события подключений и сообщений через IPC, поэтому несколько воркеров могут работать параллельно и не конфликтуют за один порт.
